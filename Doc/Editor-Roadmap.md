# Spark.Engine Editor 重构路线图

## 目标

编辑器以“可持续工作的场景工具”为目标：启动后能稳定打开世界、浏览层级、选择对象、编辑属性并观察渲染结果；所有后续能力都建立在可测试的命令、选择和资源服务之上，而不是把交互写死在 UI 构造函数里。

## 当前阶段：工作台基础（已落地）

- 顶部菜单、工具栏、场景层级、3D 视口、Inspector、状态栏的固定工作区。
- 层级树与 Inspector 共享同一个选择状态，属性编辑实时写回对象。
- 状态栏显示 Actor/Component 数量和当前选择，菜单命令给出明确反馈。
- `SetPictureInPicture` 保留为渲染视图注入点，后续可替换为真正的主视口。

## 阶段 1：编辑闭环

1. 引入 `IEditorCommand`、命令历史和事务边界，先覆盖属性修改、删除、复制、创建。
2. 为层级树增加新建 Actor、删除、重命名、拖拽父子关系和多选。
3. 工具栏接入选择/移动/旋转/缩放工具，并让视口拾取与层级选择双向同步（CPU 拾取和选择同步已落地，Gizmo 拖拽待完成）。
4. 增加快捷键路由、保存脏标记、确认弹窗和错误提示。

验收标准：一次完整的“打开场景 -> 选择 -> 修改 -> 撤销/重做 -> 保存 -> 重载”流程可重复执行，且不丢失选择和输入。

## 阶段 2：场景与资源生产力

- 场景序列化版本、增量保存、自动恢复和最近文件列表。
- 资源浏览器、搜索/过滤、缩略图、引用关系和加载错误面板。
- Inspector 分组、分类元数据、引用选择器、数组/嵌套对象编辑器。
- 可停靠面板布局、布局持久化和多视口。

验收标准：中型场景（数千节点、数百资源）下树和 Inspector 仍可搜索、滚动和编辑，刷新不会破坏正在输入的值。

## 阶段 3：调试与运行工作流

- Play/Simulate/Stop 状态机，编辑世界与运行时世界隔离。
- 控制台、日志过滤、性能计时器、RenderGraph 调试视图和 GPU 错误回传。
- Gizmo、网格/吸附、相机书签、截图和帧捕获。
- 可配置快捷键、主题和无障碍字号。

验收标准：运行时异常可定位到对象/组件，停止运行后编辑状态可恢复，调试面板不会阻塞主渲染。

## 阶段 4：扩展与团队协作

- 编辑器模块 API、面板注册、菜单贡献点、Inspector 自定义绘制器。
- 资产导入任务队列、后台编译、进度与取消。
- Git 感知的场景差异、冲突提示和只读锁定。
- UI 自动化测试、场景回放测试和崩溃恢复日志。

## 工程约束

- UI 只负责呈现和输入转发；世界修改必须经过命令/服务层。
- 每个阶段先补逻辑测试，再做 GPU 验收；布局、焦点、滚动和剪裁必须有回归测试。
- 任何耗时 IO、资源编译和反射扫描都不能运行在渲染线程。
