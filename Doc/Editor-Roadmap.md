# Spark.Engine Editor 重构路线图

## 目标

编辑器以“可持续工作的场景工具”为目标：启动后能稳定打开世界、浏览层级、选择对象、编辑属性并观察渲染结果；所有后续能力都建立在可测试的命令、选择和资源服务之上，而不是把交互写死在 UI 构造函数里。

## 当前阶段：工作台基础（已落地）

- 顶部菜单、工具栏、场景层级、3D 视口、Inspector、状态栏的固定工作区。
- 层级树、Viewport 与 Inspector 共享同一个选择状态；Ctrl 切换、Shift 区间多选已贯通，Inspector 和 Gizmo 使用最后操作的主选对象。
- 状态栏显示 Actor/Component 数量和当前选择，菜单命令给出明确反馈。
- `SetPictureInPicture` 保留为渲染视图注入点，后续可替换为真正的主视口。
- 编辑器视口相机支持右键飞行、Middle 平移、Alt+Left 轨道、滚轮推拉、`F` 聚焦和 UE 风格 `Ctrl+0..9` 保存/`0..9` 恢复会话书签；相机不进入场景资产，Reload/Play 使用独立副本。Actor 编辑器能力已与 `[SceneTransient]` 分离，内部相机和运行时辅助 Actor 默认不出现在 Outliner，也不能被用户选择、编辑、删除或复制。

## 阶段 1：编辑闭环

1. 引入 `IEditorCommand`、命令历史和事务边界，先覆盖属性修改、删除、复制、创建。
2. 为层级树增加新建 Actor、删除、重命名、拖拽父子关系和多选（多选、批量删除和 UE 风格 KeepWorld/Socket 拖放已完成）。
3. 工具栏接入选择/移动/旋转/缩放工具，并让视口拾取与层级选择双向同步（CPU 拾取、轴绘制、命中、输入路由、可配置网格吸附、选择集合和主选枢轴组变换已落地）。
4. 增加快捷键路由、保存脏标记、确认弹窗和错误提示。

Actor 复制已从空对象占位实现升级为 SceneDocument 边界深复制：保留具体类型、组件属性、共享资产、Socket 和选择组内/外挂载关系，并为副本生成新 GUID。

验收标准：一次完整的“打开场景 -> 选择 -> 修改 -> 撤销/重做 -> 保存 -> 重载”流程可重复执行，且不丢失选择和输入。

## 阶段 2：场景与资源生产力

- 场景序列化版本、增量保存、自动恢复和最近文件列表（MRU 列表和 Desktop 脏场景关闭确认已完成，自动恢复仍待补）。
- 资源浏览器、搜索/过滤、缩略图、引用关系和加载错误面板（E1 资源管理闭环和 E2 Inspector 资源引用编辑已落地：真实目录与空文件夹、目录/资产 CRUD、GUID 语义、引用保护、可恢复删除、失败回滚，以及资源选择/拖放/定位；缩略图待补）。
- Inspector 分组、分类元数据、引用选择器、数组/嵌套对象编辑器。
- 可停靠面板布局、布局持久化和多视口；World Outliner 后续增加搜索及 `Show Internal Actors` 只读过滤器。

验收标准：中型场景（数千节点、数百资源）下树和 Inspector 仍可搜索、滚动和编辑，刷新不会破坏正在输入的值。

## 阶段 3：调试与运行工作流

- Play/Simulate/Stop 状态机，编辑世界与运行时世界隔离。
- 控制台、日志过滤、性能计时器、RenderGraph 调试视图和 GPU 错误回传。
- Gizmo、网格/吸附、相机飞行/轨道/聚焦和会话视图书签（已完成）、截图和帧捕获。
- 可配置快捷键、主题和无障碍字号。

验收标准：运行时异常可定位到对象/组件，停止运行后编辑状态可恢复，调试面板不会阻塞主渲染。

## 阶段 4：扩展与团队协作

- 编辑器模块 API、面板注册、菜单贡献点、Inspector 自定义绘制器。
- 资产导入任务队列、后台编译、进度与取消。
- Git 感知的场景差异、冲突提示和只读锁定。
- UI 自动化测试、场景回放测试和崩溃恢复日志。

## 后续实施序列与开发深度

上面的“阶段 1～4”用于描述能力分类；从当前代码基线继续实施时，以本节 `E1～E9` 为权威顺序。
除明确标注可并行的工作外，后一个阶段不得绕过前置阶段的数据模型和验收门槛直接把逻辑写进 UI。

### 深度等级

| 等级 | 定义 | 适用范围 |
|---|---|---|
| L1：验证 | 主路径可以演示，允许使用临时 UI 或同步实现，不作为长期完成状态 | 技术预研、GPU 能力探针 |
| L2：日常可用 | 主路径、空状态和常见错误完整；有逻辑/布局测试，性能满足小中型项目 | 缩略图、资源预览、调试面板、停靠布局 |
| L3：工程级 | 包含事务回滚、引用安全、取消/恢复、性能基线和端到端回归 | 文件操作、场景修改、资产导入、自动恢复 |

场景与磁盘数据的写操作必须做到 L3；只读工具和视觉能力可先以 L2 交付。L1 只能作为阶段内部探针，
不能在路线图中标记为完成。

### 执行总表

| 顺序 | 阶段 | 目标深度 | 前置 | 完成门槛 |
|---:|---|---:|---|---|
| ✅ E1 | Content Browser 资源管理闭环 | L3 | 当前资产浏览器 | 真实目录、资源 CRUD、GUID 语义、引用保护与失败回滚完整 |
| ✅ E2 | Inspector 资源引用编辑 | L3 | E1 | 选择器、拖放、清空、定位和 Undo/Redo 贯通 SceneDocument/Cook |
| ▶ E3 | 缩略图与资源编辑器深化 | L2 | E1 | Texture/Mesh/Material 预览、缓存和失效更新可长期使用 |
| E4 | 后台导入任务系统 | L3 | E1 | 进度、取消、失败重试、冲突处理和原子输出不阻塞渲染线程 |
| E5 | glTF/GLB 导入深化 | L2 | E4 | 导入设置、切线、材质和纹理形成完整静态模型资产组 |
| E6 | 工作区与布局 | L2 | E2、E3 | 分栏/面板状态持久化，布局损坏可恢复默认值 |
| E7 | 调试与运行工具 | L2 | E6 | Console、日志、性能、RenderGraph/GPU 错误可定位问题 |
| E8 | 稳定性与规模性能 | L3 | E1～E7 | 自动恢复、增量扫描、虚拟化和大场景基线达标 |
| E9 | 编辑器扩展 API | L2 | E2～E8 的接口稳定 | 新资源类型或面板不再要求修改核心 `EditorUi` |

E2 与 E3 在 E1 完成后可以并行；E6 的布局基础与 E4/E5 也可并行，但 E8 必须在主要工作流稳定后统一收口。

### E1：Content Browser 资源管理闭环（L3，已完成）

交付范围：

1. 新增 `EditorAssetOperationService`，集中处理目录与 `.asset` 文件操作，UI 只提交意图和展示结果。
2. 内容浏览器以项目 `Content` 的真实目录为目录源；空文件夹也可见，不再只从 Registry 记录反推目录。
3. 支持新建文件夹、重命名、移动、复制、删除，以及对应的右键菜单和键盘入口。
4. 资源移动/重命名保持 AssetGuid；复制生成新 AssetGuid，并重写内部资产元数据。
5. 删除前检查当前场景和已登记资产的直接/传递引用；默认拒绝破坏性删除并列出引用方。
6. 磁盘与 Registry 更新采用“验证 → 临时输出/移动 → 提交 → 刷新”的事务边界；失败恢复原路径和索引。
7. 操作后保持当前目录、搜索、类型过滤和尽可能稳定的资源选择。

资源文件操作不混入场景 Undo 栈；删除优先进入可恢复位置，并使用确认对话框。场景属性和 Actor 修改仍必须走
`IEditorCommand`。首轮不做跨项目移动、版本控制锁和批量重定向器。

验收：空目录可导航；同名、非法路径、只读文件和部分失败不会留下半写状态；移动后的场景引用仍按 GUID 解析；
复制品与源资源 GUID 不同；删除被引用资产会被阻止并能定位引用方。

实现结果：`EditorAssetOperationService` 已收口 Content 写操作；资产移动/重命名保持 GUID，单资产复制生成新 GUID，
目录复制同时重写内部依赖表与 Material Payload 引用。删除先检查当前 `SceneDocument` 和 Registry 反向依赖闭包，
成功后移动到 `Saved/Trash`。扫描会移除已消失的持久记录但保留会话场景引用；操作入口包含面板按钮、资源列表右键菜单、
`F2`/`Delete`/`Ctrl+D` 和文件夹拖放。首轮仍不包含跨项目操作、版本控制锁、批量重定向器和系统文件管理器级撤销。

### E2：Inspector 资源引用编辑（L3，已完成）

交付范围：

- 为 `StaticMesh`、`Material`、`Texture2D` 等资源属性提供统一资源字段和 Asset Picker。
- 支持从 Content Browser 拖入字段、清空引用、跳转/定位资源和打开对应资源编辑器。
- 类型不兼容、资源加载失败和缺失 GUID 在字段附近显示，不用异常中断整个 Inspector。
- 引用修改通过 `IEditorCommand` 合并为单次 Undo/Redo，并正确更新场景依赖和 Cook 闭包。
- 多选时支持相同值展示和批量赋值；不同值显示混合状态。

首轮不做任意表达式绑定和跨项目资源引用。验收以保存/重载、Play/Stop 和 Cook 后引用一致为准。

实现结果：Inspector 为所有选中对象共有的 `[SceneProperty]` 资源属性生成统一字段，覆盖 `StaticMesh`、
`Material`、`Texture2D` 及其派生资源类型。字段支持 None、同值和混合值展示，Asset Picker 按类型过滤，
Content Browser 资源可直接拖入字段；`L`/`O`/`X` 分别定位、打开和清空引用。类型不兼容、缺失 Registry
记录和加载失败显示在字段附近。多对象修改通过 `PropertyBatchChangeCommand` 原子执行并作为一次 Undo/Redo；
世界资源重新登记会保留磁盘路径和传递依赖。保存/重载、Play/Stop 与 Cook 闭包端到端测试均已通过。

### E3：缩略图与资源编辑器深化（L2）

交付范围：

- Texture 使用源像素生成等比缩略图；StaticMesh 使用固定相机与灯光离屏渲染；Material 使用标准球或平面预览。
- 缩略图按 `AssetGuid + ContentHash + PreviewVersion` 缓存，源资产或预览算法变化时自动失效。
- 缩略图失败显示稳定占位图，不阻塞资源列表；列表只请求可见项。
- StaticMesh 编辑器增加旋转、缩放、聚焦、网格统计和 bounds 检查；Texture 增加通道、棋盘背景和缩放。

首轮不做用户自定义预览场景、动画缩略图和实时多资源预览。验收要求数百资源滚动时不重复上传同一预览纹理。

当前进展：Content Browser 已将创建入口统一为 `Create → Folder / Material`，右键菜单提供相同操作；
Material 通过事务式资产服务写入、校验并登记，失败不保留临时文件或 Registry 脏记录。其它资源类型创建、
缩略图缓存和资源编辑器预览交互仍按本阶段继续实施。

### E4：后台导入任务系统（L3）

交付范围：

- 统一 `EditorImportTask` 状态机：Queued、Running、Succeeded、Failed、Canceled。
- 文件读取、图片解码、glTF 解析和 CPU 资产构建在后台执行；Registry 提交和 UI 通知回到编辑器线程。
- 提供进度、取消、失败详情、重试和任务历史；取消或失败不得覆盖现有有效资产。
- 保存来源路径、导入设置、内容哈希和导入器版本，支持 Reimport 与冲突策略。
- 输出先写临时文件，校验成功后原子替换；批量导入给出逐项结果。

验收：大型 GLB/图片导入时视口和输入保持响应；取消、异常和进程中断不产生半个 `.asset`。

### E5：glTF/GLB 导入深化（L2）

交付范围：

- 导入面板支持坐标轴、单位缩放、保留/合并 Mesh、法线策略、切线生成和命名冲突策略。
- 导入 glTF PBR Material、基础纹理和资源依赖，保持一个源模型生成的资产组可重新导入。
- 明确处理多 Mesh、多 Primitive、无索引几何和常见顶点编码；不支持项形成可定位诊断。
- Reimport 尽量保持已有 Mesh/Material/Texture AssetGuid，避免场景引用失效。

Skeleton、SkeletalMesh、Animation 和 Morph Target 作为独立里程碑，不纳入本轮 StaticMesh 导入深化。

### E6：工作区与布局（L2）

交付范围：

- 分栏尺寸、面板显示状态、活动文档和标签顺序持久化到 `Saved`。
- 支持基础停靠、关闭/重新打开面板和恢复默认布局；非法或旧版本布局安全回退。
- 资源编辑器继续使用文档标签；多 Viewport 在单一布局稳定后再接入。

首轮不做跨操作系统原生浮动窗口和复杂多显示器恢复。

### E7：调试与运行工具（L2）

交付范围：

- Console 与结构化日志：级别、类别、文本过滤，支持定位关联 Actor/Component/Asset。
- 帧耗时、Draw Call、可见对象、资源上传与显存近似统计。
- RenderGraph 只读视图和 GPU 错误面板；从错误跳转到 pass、资源或资产记录。
- Play/Stop 下区分 EditorWorld 与 RuntimeWorld 数据，停止后不保留失效对象引用。

首轮帧捕获只提供引擎级快照和截图；外部 GPU 调试器集成后置。

### E8：稳定性与规模性能（L3）

交付范围：

- 定时自动保存、崩溃恢复清单和恢复/丢弃流程；正式保存成功后清理对应恢复文件。
- Content/Registry 增量扫描和变更合并，避免每帧全量签名与列表重建。
- 层级树和资源列表虚拟化；Inspector 缓存元数据但不得覆盖正在编辑的输入。
- 建立 1000/5000/10000 Actor、数百/数千资产的刷新、搜索、选择和内存基线。
- 增加长时间运行、失败注入和恢复测试。

验收指标先记录当前基线，再为每种规模设定可重复的测试预算；不得用降低正确性或跳过引用校验换取数据。

### E9：编辑器扩展 API（L2）

交付范围：

- 面板、菜单/工具栏命令、资源编辑器、Importer 和 Inspector Drawer 注册接口。
- 注册项具有稳定 ID、生命周期和冲突诊断；卸载后不留下事件订阅或 UI 节点。
- 核心编辑器只依赖抽象注册表，新资源类型不需要修改 `EditorUi` 的类型分支。
- 提供至少一个外部示例模块和兼容性测试。

首轮不承诺插件热重载、二进制兼容和在线市场；这些能力必须建立在扩展 API 版本化之后。

### 统一完成定义

每个阶段只有同时满足以下条件才可标记完成：

1. 主路径、空状态、取消/失败路径有明确 UI 反馈。
2. 世界修改走 Command/Service；IO、解析和编译不阻塞渲染线程。
3. 新增逻辑测试、必要的布局测试和至少一个端到端验收场景。
4. 全量测试不得低于当前 `224/224` 基线，Engine/Editor 构建无新增警告。
5. 更新本路线图、实施计划和相关设计文档；已知限制必须写明，不以“控件已显示”代替功能完成。

## 工程约束

- UI 只负责呈现和输入转发；世界修改必须经过命令/服务层。
- 每个阶段先补逻辑测试，再做 GPU 验收；布局、焦点、滚动和剪裁必须有回归测试。
- 任何耗时 IO、资源编译和反射扫描都不能运行在渲染线程。
